# Offline STT preparation

The optional Windows x64 installer downloads official whisper.cpp 1.8.3 CPU binaries and the multilingual base model. It does not change the selected voice backend. Human microphone recognition remains unresolved; a successful synthesized-speech decode is not evidence of a human conversation.

Sources: [upstream](https://github.com/ggml-org/whisper.cpp), [pinned release](https://github.com/ggml-org/whisper.cpp/releases/tag/v1.8.3), [model repository](https://huggingface.co/ggerganov/whisper.cpp). Version 1.8.3 is a pinned binary release, not a claim to be the latest source version. The model revision, sizes and SHA-256 values are fixed in the installer. Each required native dependency is checked against the release-derived digest map. Existing mismatched files are preserved and rejected. Upstream MIT license is in `docs/third-party/whisper.cpp-LICENSE.txt`.

Run `node scripts/install-local-stt.mjs`. Then set `ZERO_WHISPER_TESTS=1` and run `node --test test/whisper-native-real.test.mjs`. The opt-in REAL_OS/INTEGRATION test creates genuine Windows TTS, invokes the real CPU decoder, requires every word to match, records PASS or FAIL, and removes its temporary public-audio fixture. It does not record microphone audio or play sound. See verification/2026-11-10/whisper-public-tts.json.

The shared download helper now supports pinned non-GGUF binary assets. The GGUF wrapper still forces its magic header regardless of caller options. Actual loopback HTTP transfer tests cover generic binary acceptance and mandatory GGUF rejection along with existing corruption, truncation, oversize, cancellation and file preservation checks. These are INTEGRATION checks, not external service or inference proof.

ZERO now supports explicit `recognitionBackend: 'whisper'` on VoiceEngine and `voiceRecognitionBackend: 'whisper'` on the native host, or `ZERO_VOICE_RECOGNITION_BACKEND=whisper` for host startup. The default remains Windows recognition. Invalid selections fail before host state initialization. Missing or altered pinned assets fail without silently switching recognizers. Microphone capture, speech synthesis and playback continue through the Windows device backend.

The Whisper recognizer sends binary WAV over stdin and keeps microphone audio off disk. It checks pinned dependencies/model, bounds runtime/output, waits for native close on cancellation, and reports unknown-language errors even though this CLI can exit zero for them. No confidence or timestamps are invented. Actual native decode through VoiceEngine, spawned-process cancellation, subsequent recovery and missing-language rejection passed. Actual shared host voice/assistant/typed continuation also passed with the selected backend class asserted. Initial empty-stdout and masked-native-error test failures are retained in the evidence. See verification/2026-11-10/whisper-selectable-integration.json.

Actual prompted human headset recognition subsequently passed with device0 Rockerz480: all six expected words detected. The earlier attempt remains failed; the user clarified that no sentence was spoken during that attempt. See verification/2026-11-10/whisper-headset-microphone.json. This selected phrase does not establish general recognition accuracy.

The actual headset-to-shared-assistant conversation also passed, including native reply playback, same-chat typed recall and the user's confirmation of clear audible output. See verification/2026-11-10/whisper-human-conversation.json. This uses an explicit end of utterance and is not automatic VAD completion acceptance.

Actual native playback was cancelled by microphone VAD, and the user confirmed speaking and hearing playback stop. However, the stronger adjacent interruption phrase recognition assertion failed, so the overall barge-in test remains FAIL and recovery was not reached. See verification/2026-11-10/whisper-human-barge-in.json. Energy VAD has no echo cancellation and is not established as intent-aware or noise-resistant. Automatic VAD conversation completion and complete interruption acceptance remain open.

Human tests can select `ZERO_VOICE_INPUT_DEVICE_ID` and enable `ZERO_VOICE_HUMAN_PROMPT_AUDIO=1`; the audible cue omits the target phrase and capture reports aggregate input levels without saving raw audio. `ZERO_VOICE_HUMAN_CONVERSATION=1` selects actual microphone input and actual reply playback in the existing conversation test. The separate opt-in human barge-in test uses `ZERO_VOICE_HUMAN_BARGE_IN=1`.
